Karu（軽）は、WPF + WebView2（Chromium）で作った個人用ブラウザです。目的はひとつ、「本物のChromiumエンジンを使いながら、動画視聴込みでメモリ使用量を徹底的に抑える」こと。タブバーもURLバーもツールバーもなく、操作はすべてキーボード（Vim風）で行います。

## なぜ作ったか

Chromium系ブラウザはメモリを大量に消費しますが、世に出回っている「軽量ブラウザ」の多くは機能を削るか、そもそもChromiumではない（ためサイトの挙動・DRM・コーデック対応が本家と異なる）という問題があります。Karuは本物のWebView2（Edge/Chromeと同じエンジン）を使いつつ、以下で軽量化しています。

- 背面タブを段階的にサスペンド・休眠させる
- 速度より低メモリを優先して数十個のChromiumフラグ・機能を調整する
- 動画再生をまるごと [mpv](https://mpv.io/) に肩代わりさせ、そのタブのChromium側消費をほぼゼロにできる
- ブラウザchrome自体（タブバー・URLバー・ツールバー）を高さ40pxのドラッグバー1本に削ぎ落とし、代わりにキーボード操作のオーバーレイで全操作をまかなう

## 主な機能

- **クロームレスUI** — タブバーもURLバーもなし。全操作はキーボードオーバーレイと高さ40pxのタイトルバーのみ。
- **3段階タブライフサイクル** — Active(表示中) → Suspended(WebView2の`TrySuspendAsync`、非表示15秒後) → Hibernated(WebViewを完全破棄しURL・動画再生位置のみ保持、タブの「温存度」に応じて3〜10分)。セッション復元時も表示タブ以外は最初から休眠させ、起動時のメモリスパイクを避けます。空きメモリが閾値を切ると緊急休眠も発動。音声再生中のタブには一切手を出しません。
- **Vim風キーボード操作層** — 全ページに自動注入。`j/k/h/l`スクロール、`d/u`半ページ、`gg/G`先頭/末尾、`f/F`リンクヒント、`H/L`戻る/進む、`yy`URLコピー、`?`ヘルプ、など。
- **キーボードで完結するタブ一覧**（`Ctrl+Tab`）と**ブックマーク一覧**（`b`） — どちらも`j/k`+`Enter`で選択・決定、同じキーをもう一度押せば閉じます。
- **YouTube向けの作り込み** — プレーヤー内広告スキップ、画質上限、H.264強制（VP9/AV1のデコード負荷回避）、コメント・関連動画・ショート棚を隠す集中モード、プレーヤー内の再生速度ボタン。スキップボタンは**CDP経由で注入した本物のクリック（信頼済み入力）**で押します。YouTubeのプレーヤーはスクリプトからの`click()`（`isTrusted: false`）を広告ブロッカーとして記録したうえでスキップを実行せず、さらに不可視のおとりスキップボタンまで置いているため、Karuは「その座標に実際に見えているボタン」だけを押します。広告内のシークはしません。YouTubeは広告中のシークをすべて報告し、再生開始前に末尾へ飛ぶと10秒の読み込みタイムアウトまで本編に進まないためです。代わりに広告はKaruのロゴの被いで隠したうえでミュート+2.4倍速で流し、スキップボタンが出た瞬間に押します。プレーヤーは広告が再生開始から実時間の2.5倍より速く進むと検知するので、最初の0.3秒だけ等速にして余裕を取っています。被いはクリックするとその広告の間だけ外れます。`settings.json` の `YouTubeAdSpeedUp` / `YouTubeAdCover` を `false` にすると、それぞれ等速/被いなしになります(ミュートとスキップボタンの自動クリックは続きます)。
- **[mpv](https://mpv.io/) 連携**（`Ctrl+M`） — 現在の動画をyt-dlp経由でmpv再生に切り替え、再生成功を確認したらページを軽量なプレースホルダーに差し替え（再生位置は引き継いで戻れます）。
- **ページ翻訳**（`Ctrl+Shift+Y`） — Chromeの「このページを翻訳」相当。本文をその場で日本語に置き換え、もう一度押すと原文に戻ります（翻訳⇄原文のトグル）。リンクや`<code>`はそのまま保ったまま日本語の語順に並べ替えます。詳細は[ページ翻訳](#ページ翻訳)を参照。
- **タブを別ウィンドウへ分離**（`Ctrl+Shift+D`） — 現在のタブを新しいウィンドウに切り出します（左右に並べて見たいとき用）。分離したウィンドウを閉じたときは、そのタブを保存済みセッションへ合流させます（上書きしません）。
- **通常ブラウザとして振る舞う** — `navigator.webdriver` を隠し、低スペック偽装はYouTubeに限定することで、Cloudflareなどのボットチェックに「自動化ブラウザ」と誤認されにくくしています。
- **検閲回避用ネットワーク経路** — HTTP(S)/SOCKS5プロキシに対応。ページ本体だけでなく、翻訳とTwitch処理の通信も同じプロキシを通します。プロキシ使用時はWebRTCの非プロキシUDPとQUICも止め、別経路から接続元IPが漏れるのを防ぎます。
- **広告・トラッカーブロック** — 内蔵のドメインブロックリスト（`%APPDATA%\Karu\blocklist.txt`）で遮断します。ただし、YouTubeが広告ブロッカー検出のおとりにしているdoubleclickのURL2つ（`ad_status.js` と `pagead/id`）は通します。止めても広告は減らず、YouTubeに広告ブロッカー使用と報告されるだけだからです。**拡張機能のサイドロードは広告ブロックには使えません** — WebView2はcontent scriptを実行せず、MV2拡張のwebRequestによる遮断も効かないことを実測で確認しています（uBlock Originを置いても何も遮断されず、常駐メモリだけ増えます）。
- **Twitchの広告除去** — Twitchは広告を配信本体と同じHLSストリームに縫い込む（サーバー側広告挿入）ため、ドメイン単位のブロックでは触れません。Karuはプレイリストを見て広告区間を検知し、クリーンなプレイリストを取り直して差し替えます。実配信のミッドロールで検証済み（43回検知・43回差し替え成功、画質は元のまま）。**効くのはミッドロール（視聴中に挟まる広告）だけです** — 配信を開いた直後のプリロールは、取り直した先のセッションも同じくプリロールを引くため回避できません。差し替えできなかった広告は、プレーヤー部分だけを覆って消音します（ページ全体は覆いません）。`settings.json` の `TwitchAdBlock` でOFFにできます。
- **セッション復元、パスワード保存/自動入力、ブックマーク。**
- **テキストカーソルモード、CDP経由の動画フルスクリーン、実測メモリ使用量の表示。**

## ページ翻訳

`Ctrl+Shift+Y`（または右上の`≡`メニュー）で、Chromeの「このページを翻訳」相当に本文を日本語へ置き換えます。もう一度押すと原文に戻る翻訳⇄原文のトグルで、再翻訳・復元はキャッシュを使うので瞬時です。

テキストを断片ごとに訳すのではなく、リンクや`<code>`などのインライン要素をブロック単位でまとめて翻訳します。そのため**リンクやコードは中身を保ったまま、日本語の語順に合わせて正しい位置に並び替わります**（`<code>`などのコードは中身を翻訳しません）。単純にテキストノードごとに訳すと、リンクで分断された文の語順が崩れたりリンク位置がずれたりしますが、それを避けています。

SPA（シングルページアプリ）にも対応しています。YouTubeのようにページを実際に読み込み直さず中身だけ差し替えるサイトでは、トグルが「実質別のページになった」ことを検知し、古いキャッシュの切替ではなく新しい内容を翻訳し直します。

翻訳にはGoogle翻訳の無料エンドポイントを使います（APIキー不要、通信はアプリ側で実行）。メニューやヘッダなど繰り返し出てくる文言はアプリ全体でキャッシュされるため、同じサイト内を移動し続けても新しい部分だけを翻訳します。非公式のため、巨大なページではレート制限に当たることがあります（レート制限応答は1回だけ自動再試行し、それでも訳せなかった部分は原文のまま残ります）。

## 必要環境

- Windows 10/11
- [.NET 10 デスクトップランタイム](https://dotnet.microsoft.com/download/dotnet/10.0)
- [WebView2 ランタイム](https://developer.microsoft.com/microsoft-edge/webview2/) — Edgeが入っているWindows 11/10ならほぼ標準で入っています
- [mpv](https://mpv.io/)（任意、`Ctrl+M`用） — `winget install mpv-player.mpv-CI.MSVC`

## インストール

[Releases](../../releases) から最新のzipをダウンロードして展開し、`Karu.exe` を実行してください。

> Karuはまだコード署名していないため、初回実行時にWindows SmartScreenが警告を出すことがあります。「詳細情報」→「実行」で進めます。署名していない理由は下記「[SmartScreenについて](#smartscreenについて)」を参照するか、自分でソースからビルドしてください。

## ソースからビルド

```
dotnet publish src/Karu.csproj -c Release -o dist
```

`dist/` にフレームワーク依存ビルドが出力されます（実行先マシンに.NET 10 デスクトップランタイムが必要です）。

## 設定

設定・ブックマーク・広告ブロックリスト・サイドロードした拡張機能は、すべて `%APPDATA%\Karu` に保存されます。WebView2自体のプロファイルデータ（Cookie・ログインセッション）は `%LOCALAPPDATA%\Karu\WebView2Data` に保存されます。アプリ内メニュー（右上の`≡`ボタン）から設定フォルダを開けます。`settings.json` は初回起動時に生成され、ネットワーク設定の変更は再起動後に反映されます。

検閲回避に関係する設定例:

```json
{
  "ProxyServer": "socks5://127.0.0.1:9050",
  "EnableBrowserProtections": true
}
```

- `ProxyServer`: `http://host:port`、`https://host:port`、`socks5://host:port`。空文字ならシステム設定を使います。認証情報をURLへ埋め込む形式は、プロセス一覧への漏えいを防ぐため拒否します。書式が通らない値は、起動時の警告ダイアログとメニュー表示で知らせたうえでプロキシなしで動作し、`settings.json` の値はそのまま残します。
- `EnableBrowserProtections`: 既定の`true`ではサイト分離、SmartScreen、WebView2追跡防止を維持します。`false`はこれらを外して旧版相当までメモリを詰める上級者向け設定ですが、任意サイトの閲覧には推奨しません。

`ProxyServer` の使用中は、Karuの設定を引き継げない外部mpv・Edgeへの引き渡しを無効にします。システム全体を通すVPN等を使う場合は `ProxyServer` を空にすれば、これらの外部連携も利用できます。

Karu自身は中継サーバーを内蔵しません。DNS/IP/SNIレベルの遮断を越えるには、名前解決も中継側で行う到達可能な外部プロキシ、VPN、Tor等が必要です。WebView2にはアプリ単位の正式なDoH設定APIがないため、効かない可能性のあるChromium内部フラグを「DoH対応」としては扱っていません。

環境変数 `KARU_PROFILE_DIR` を設定すると、そのフォルダ配下を設定とWebView2データの置き場にして起動します（普段のセッションに触れずにビルドを試すとき用）。

`%APPDATA%\Karu\extensions\` に非パッケージ版のChromium拡張を置くと読み込まれますが、**広告ブロック目的では置かないでください**。WebView2ではcontent scriptもMV2のwebRequest遮断も動かないため何も遮断されないうえ、拡張が存在すると内蔵ブロックリストのほうが無効化されます（実測: 拡張レンダラーだけで約105MB消費し、遮断はゼロ）。

## SmartScreenについて

KaruのWebView2内SmartScreen・サイト分離・追跡防止は既定で有効です。初回実行時にWindowsが出す「認識されないアプリ」の警告は、配布バイナリが未署名で実績が少ないことによるもので、WebView2内の保護設定とは別です。気になる場合は上記の手順でソースからビルドできます。
